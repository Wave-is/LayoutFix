# LayoutFix — продуктовое и техническое видение

Статус документа: действующая спецификация проекта.

Фактическое выполнение критериев и незакрытые внешние release gates фиксируются в `READINESS.md`.

`roadmap.md` отражает раннюю концепцию и сохраняется только как исторический материал. Если требования документов расходятся, приоритет имеет этот файл.

## 1. Назначение продукта

LayoutFix — локальный Windows-помощник для многоязычного ввода. Он сокращает время на исправление текста, набранного в неправильной раскладке, осторожно исправляет очевидные ошибки раскладки во время набора и помогает переводить текст на другие языки.

Программа должна восприниматься как часть клавиатуры: работать незаметно, предсказуемо и никогда не подвергать риску пользовательский текст или стабильность активного приложения.

## 2. Три продуктовых направления

### 2.1. Ручное исправление раскладки

Базовая и обязательная функция продукта.

- Преобразовать выделенный текст по глобальному шорткату.
- Если выделения нет — преобразовать последнее слово слева от каретки.
- Сохранить регистр, пунктуацию, переносы строк и Unicode.
- При необходимости переключить активное приложение на целевую раскладку.
- Поддержать мгновенную отмену последней операции.
- При любой неопределённости отменить операцию без изменения текста.

### 2.2. Автоматическое исправление

Опциональная функция, которая включается только после объяснения её поведения пользователю.

- Анализировать последовательность физических клавиш, активную раскладку, регистр и границу слова.
- Исправлять только случаи с высокой уверенностью.
- Не исправлять валидные слова текущего языка, пароли, исключения пользователя и ввод в запрещённых приложениях.
- Поддерживать отмену, обучение на отменах, пользовательские исключения и явные пары автозамены.
- Не запускать пересекающиеся фоновые исправления и не воздействовать на окно, потерявшее фокус.

### 2.3. Машинный перевод

Дополнительный модуль, не влияющий на надёжность базового ввода.

- Перевести выделение, последнее слово или текст в отдельном окне.
- Режимы результата: предварительный просмотр, заменить, скопировать.
- Онлайн-провайдеры используются только с явным информированием пользователя.
- Офлайн-модели выполняются в отдельном worker-процессе.
- Поддерживаются отмена запроса, таймауты и проверка фокуса перед заменой.
- История перевода отключаема; пользовательский текст не пишется в логи.

## 3. Неприкосновенные гарантии

1. LayoutFix не теряет и не повреждает пользовательский текст.
2. LayoutFix не вставляет результат в окно или поле, отличное от исходного.
3. Неуспешная операция не меняет выделение, каретку, раскладку и clipboard.
4. Clipboard сохраняется и восстанавливается во всех форматах, а не только как plain text.
5. Keyboard hook не выполняет файловый ввод-вывод, сетевые запросы, загрузку словарей, clipboard-операции или бизнес-логику.
6. Каждое автоматическое изменение отменяемо.
7. Автоисправление ничего не делает при низкой уверенности.
8. Текст, нажатия клавиш и переводы не логируются по умолчанию.
9. Исключения приложений применяются ко всем функциям, включая автоисправление.
10. Ошибка сети, GPU или локальной модели не останавливает ручное исправление раскладки.

## 4. Целевая архитектура

### 4.1. Input Monitor

- Выделенный поток с Windows message loop.
- `WH_KEYBOARD_LL` используется только там, где действительно требуется наблюдение или подавление события.
- Обычные глобальные сочетания по возможности регистрируются через `RegisterHotKey`.
- Состояние модификаторов строится из согласованных `keydown`/`keyup`, а не из `GetAsyncKeyState` внутри hook callback.
- Callback нормализует событие, помещает его в ограниченную очередь и немедленно возвращает управление.
- Ошибки установки и конфликты шорткатов видны в интерфейсе.

### 4.2. Input Event Queue

- Все действия сериализуются и имеют cancellation token.
- Устаревшие события отбрасываются по идентификатору фокуса и поколению input session.
- Повторный шорткат не исчезает молча: он ставится в очередь, заменяет допустимую операцию либо получает понятный отказ.

### 4.3. Text Transaction Engine

Каждая мутация текста проходит как транзакция:

1. Зафиксировать `HWND`, процесс, thread id, активный контрол и раскладку.
2. Выбрать адаптер получения текста.
3. Снять полный snapshot clipboard, если необходим clipboard fallback.
4. Получить выделение или последнее слово с таймаутом.
5. Рассчитать результат без воздействия на UI.
6. Повторно проверить фокус и состояние исходного окна.
7. Выполнить замену.
8. Подтвердить завершение либо выполнить rollback.
9. Восстановить clipboard в `finally`.
10. Сохранить минимальные данные для undo без долговременного хранения пользовательского текста.

Порядок адаптеров:

1. UI Automation / TextPattern.
2. Win32 Edit и RichEdit API.
3. Специализированный адаптер приложения.
4. Безопасный clipboard fallback.

### 4.4. Auto-correction Engine

- Буфер хранит key tokens: scan code, virtual key, shift/caps/AltGr, HKL, timestamp и target identity.
- Словари загружаются и валидируются заранее, вне hook.
- Для каждого активного языка строится кандидат слова из одной физической последовательности.
- Confidence учитывает валидность исходного слова, валидность и частотность кандидата, длину, язык, контекст, исключения и историю отмен.
- Исправление выполняется одной последовательной очередью и отменяется при смене фокуса или продолжении ввода, делающем операцию устаревшей.

### 4.5. Translation Worker

- Основной tray/input-процесс не ссылается на LLamaSharp и GPU backend.
- Локальная модель запускается в отдельном процессе и общается с UI по ограниченному IPC-контракту.
- Падение worker автоматически освобождает ресурсы и не влияет на hook.
- Онлайн-провайдер имеет официальный контракт, таймаут, отмену, лимит размера и понятную политику приватности.

## 5. Пользовательский опыт

### Первый запуск

- Выбрать две или три основные раскладки.
- Проверить основной шорткат в встроенном тестовом поле.
- Объяснить режимы: ручное исправление, автоисправление, перевод.
- Автоисправление по умолчанию выключено до явного согласия пользователя.
- Показать, что онлайн-перевод отправляет выделенный текст выбранному провайдеру.

### Постоянное использование

- Значок трея показывает: активно, приостановлено, ошибка hook, выполняется операция.
- Быстрое меню: пауза, исправить, отменить, переводчик, настройки, выход.
- Ошибки сообщаются ненавязчиво и без утечки текста.
- Для каждого приложения можно выбрать: всё разрешено, только ручные действия, полностью выключено.
- Повышенные приложения и несовместимые поля получают честный статус «не поддерживается», а не ложное успешное выполнение.

## 6. Приватность и безопасность

- Логи содержат только тип действия, длительность, код результата, layout ids, process category и технические error codes.
- Запрещено писать в лог нажатые клавиши, исходный текст, преобразованный текст, переводы, clipboard contents и пути пользовательских документов.
- История переводов выключается и очищается из интерфейса.
- Password/secure controls всегда исключены из автоисправления и захвата текста.
- Настройки и пользовательские словари хранятся в `%LocalAppData%\LayoutFix`, сохраняются атомарно и имеют явную версию схемы.
- Сетевые функции выключены без выбора пользователя.

## 7. Совместимость

Поддержка приложения считается подтверждённой только после тестирования конкретного класса полей.

Минимальная матрица:

- Win32 Edit/RichEdit и Notepad.
- WinForms и WPF.
- Word и Excel.
- Chrome/Edge: input, textarea, contenteditable.
- Electron-приложения.
- Telegram/мессенджеры.
- Adobe Premiere Pro, After Effects и Photoshop: текстовые поля, переименование, текстовые инструменты; нетекстовые объекты должны безопасно игнорироваться.
- Обычные и повышенные процессы.
- Несколько мониторов, разные DPI, RDP.
- EN/RU/UK, затем остальные раскладки, AltGr/dead keys и IME.

## 8. Стратегия тестирования

### Unit tests

- Преобразование всех символов каждой раскладки, регистр и punctuation.
- Неоднозначные и смешанные строки.
- Hotkey parser и state machine для всех `keydown`/`keyup` последовательностей.
- Confidence engine и пользовательские исключения.
- Settings migrations и атомарное сохранение.
- Очереди, cancellation, focus generations и undo.

### Integration tests

- Clipboard snapshot/restore для Unicode, HTML, RTF, bitmap, file drop и custom formats.
- Медленный и заблокированный clipboard owner.
- Focus change на каждом этапе транзакции.
- Частичный или заблокированный `SendInput`.
- Повторные шорткаты, удержание модификаторов и autorepeat.
- Падение translation worker и сетевой timeout.

### Windows E2E tests

- Выделенная Windows 10/11 VM или физическая машина с активной unlocked desktop session.
- Автоматизированные прогоны в тестовых Edit/RichEdit/WPF/browser полях.
- Ручной и автоматизированный compatibility suite в Office и Adobe.
- Stress/soak run с быстрым вводом и сменой фокуса.

## 9. Release gates

Продукт не считается стабильным, пока одновременно не выполнено следующее:

- Чистая машина может воспроизводимо собрать solution и installer.
- Все unit и integration tests проходят в CI.
- Полный Windows E2E suite проходит на поддерживаемых Windows 10 и 11.
- Не менее 1 000 последовательных ручных преобразований в стандартном поле проходят без пропуска, зависания и повреждения clipboard.
- Ни один тест смены фокуса не приводит к вводу в другое окно.
- Clipboard после успешной и неуспешной операции полностью восстановлен во всех тестируемых форматах.
- Автоисправление проходит stress test без перестановки, потери или дублирования символов.
- Adobe compatibility suite не вызывает зависаний; нетекстовые выделения игнорируются.
- Логи и диагностические bundle не содержат пользовательского текста.
- Установка, автозапуск, обновление и удаление проверены из-под обычного пользователя.
- Онлайн- и офлайн-перевод имеют таймауты, отмену и не влияют на доступность ручных шорткатов.

## 10. Порядок реализации

### P0 — воспроизводимая база

- Исправить solution и устаревшие тестовые проекты.
- Добавить build/test gates в CI.
- Нормализовать версии и артефакты выпуска.
- Исправить settings path, миграции и приватность логов.
- По умолчанию выключить небезопасное автоисправление до завершения P1.

### P0 — надёжный ручной сценарий

- Переписать input monitor и hotkey state machine.
- Реализовать Text Transaction Engine и полный clipboard snapshot.
- Добавить focus validation, rollback и undo.
- Подтвердить работу на базовой compatibility matrix.

### P1 — автоисправление

- Переписать word tracking и confidence engine.
- Подключить blacklist, secure-field detection, user exceptions и user autocorrect.
- Добавить stress tests и beta UX.

### P2 — перевод

- Вынести локальную модель в worker. Реализовано: основной процесс не содержит зависимости LLamaSharp.
- Перейти на поддерживаемый online provider contract. Реализовано: Google Cloud Translation Basic v2, ключ хранится в Windows Credential Manager.
- Добавить preview, cancellation, privacy controls и glossary.

### P3 — расширение совместимости

- Дополнительные языки, layout variants, AltGr/dead keys/IME.
- Специализированные адаптеры проблемных приложений.
- Оптимизация ресурсов, accessibility и полировка UX.

## 11. Текущее правило разработки

Новые пользовательские функции не добавляются, пока незакрытый P0-дефект способен:

- удалить или изменить не тот текст;
- потерять clipboard;
- воздействовать на другое окно;
- зависнуть в hook callback;
- записать пользовательский текст в лог;
- остановить работу шорткатов без видимой ошибки.
